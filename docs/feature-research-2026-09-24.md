# SceneShelf: ドラッグ追加と選択オブジェクトからのシーン作成

調査日: 2026-09-24。この文書は実装前の設計メモです。現在の機能と操作方法は [`README.md`](../README.md) を参照してください。

## 根拠

- AviUtl2 作者配布の最新版は 2.1.10（2026-09-19）。[公式配布ページ](https://spring-fragrance.mints.ne.jp/aviutl/index.php)
- SceneShelf は `RequiredVersion() == 2011000` の `.aux2`。現行実装は [`src/main.cpp`](../src/main.cpp)、利用可能な API の宣言は同梱の [`plugin2.h`](../vendor/aviutl2_sdk/plugin2.h) で確認した。
- 現在の「タイムライン追加」は `add_scene()` でシーン参照オブジェクトをカーソル位置に作る。`TVN_BEGINDRAGW` から始まるドラッグは、ツリー内のフォルダ移動・並び替えだけを扱い、ツリー外で離した場合は何も追加しない。
- 現在の「新規シーン」は `create_scene()` で空のシーンを作る。タイムライン上の複数選択は読んでいない。

## 1. シーンをタイムラインへドラッグして追加

実現可能。既存のツリードラッグ処理を拡張する。

1. シーン行からのドラッグ中はシーン ID を保持する。フォルダ行には適用しない。
2. ボタンを離したとき、ツリー内なら既存の並び替え処理を続ける。ツリー外ならマウス位置をスクリーン座標に変換する。
3. `EDIT_SECTION::pos_to_layer_frame(x, y, &layer, &frame)` で、離した位置がタイムラインのレイヤー・フレーム上か判定する。`get_mouse_layer_frame()` は SceneShelf 側の最後のマウス移動位置に依存するため、この用途では明示座標版を使う。
4. 有効な位置なら `call_edit_section_param()` 内で、既存の `add_scene()` と同じシーン参照エイリアスを `create_object_from_alias()` に渡す。現在開いているシーン自身への参照は拒否する。
5. ドロップ位置が無効、配置先が使用中、エイリアス作成が失敗した場合は追加しない。操作を取り消せるよう、作成は一つの編集セクションに収める。

これは SceneShelf がホストのタイムライン座標を調べて直接オブジェクトを作る方式。`register_file_drop_handler()` はファイルを**受け取る** API であり、シーン行を外へドラッグする本件の実装経路ではない。現在の `SetCapture()` を使うドラッグが、ドッキング状態のパネルからタイムラインまで維持されるかは実機で確認する。

初期仕様は既存ボタンと同じ長さ 150 フレームを使い、ドラッグ先のレイヤーとフレームを採用する。長さの自動決定や配置先が埋まっている場合の空きレイヤー探索は別の仕様判断とする。

## 2. 選択した複数オブジェクトだけで新規シーンを作る

SDK 上の構成要素は揃っている。実機でエイリアスの再生成結果を検証する必要がある。

- `get_selected_object_num()` と `get_selected_object(index)` で、現在のシーンで選択中のオブジェクトを列挙できる。
- 各オブジェクトの `get_object_alias()` と `get_object_layer_frame()` で設定、相対レイヤー、相対時刻を記録できる。返されたエイリアス文字列は寿命が短いため、読み取りコールバック内で即座にコピーする。
- `create_scene()` は新しいシーンに切り替える。ただし読み取り／編集ロック中には呼べない。選択内容のスナップショット取得 → ロック解放 → シーン作成 → 新しいシーンで `call_edit_section_param()` により `create_object_from_alias()` を実行、の順が必要。
- タイムラインの右クリックには `register_object_menu_param()` で「選択オブジェクトからシーン作成」を追加できる。ホストのメニュー処理中にシーンを切り替えないよう、選択内容を先に確定し、自ウィンドウへのメッセージで作成処理を遅延するのが安全。
- SceneShelf の「新規シーン」ボタンは、選択オブジェクトがあればそのコピーから作成し、未選択なら現行どおり空のシーンを作る仕様にできる。ボタンクリック後にも複数選択状態が保持されるかは実機確認が必要。

提案する配置規則は、選択中の最も早い開始フレームを新シーンのフレーム 0、最上位レイヤーを新シーンのレイヤー 0 とし、他のオブジェクトの相対位置・長さを保つもの。元のシーンのオブジェクトはコピー元として残す。新シーンの解像度、フレームレート、サンプルレート、背景色は元シーンの設定を引き継ぐ。SceneShelf でフォルダを選択していた場合は、現行の `create_scene()` と同じくその仮想フォルダに分類する。

### 制約と確認事項

- `create_scene()` とオブジェクト追加を一つの編集ロック／Undo 単位にまとめる API はない。途中でエイリアス再生成が失敗すると新シーンが一部だけ作られ得るため、事前に全オブジェクトを取得・検査し、失敗内容を明示する必要がある。
- エイリアス内のフレーム情報は `create_object_from_alias()` の `length` 引数より優先される場合がある。実際の `.object` 出力で、長さ・相対位置の再現を確認する。
- グループ制御、カメラ、クリッピング、音声、複数区間、シーン参照、外部メディア、サードパーティ効果は選択した集合だけで成立するとは限らない。未選択の周辺オブジェクトを暗黙にコピーしない。
- 右クリックが複数選択を保持するか、SceneShelf のボタンへフォーカスを移しても複数選択を列挙できるかを確認する。

## 実装前の検証順

1. テスト用プロジェクトで、ツリーからタイムラインへのドロップ座標、無効領域、占有済みレイヤー、Undo/Redo を確認する。
2. 単一・複数選択のエイリアスを出力し、相対時刻・レイヤー・長さの復元を確認する。
3. ボタンと右クリックの双方で同じ結果になること、元シーンが残ることを確認する。
4. 保存／再読み込み、上記の特殊オブジェクト、失敗時の部分作成を検証する。
5. テスト環境で安定した後にリリース用ビルドを作る。本番インストールは別途行う。
